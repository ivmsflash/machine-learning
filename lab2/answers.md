# Ответы на вопросы для самопроверки

---

## 1. Какие параметры модели определяются термином «гиперпараметры модели»?

Это **параметры, задаваемые до обучения**, которые не подбираются алгоритмом по данным, а выбираются исследователем. Примеры: `C` и `solver` у логистической регрессии, `n_neighbors` у KNN, `n_clusters` у KMeans, `degree` у полиномиальной регрессии, `max_depth` у решающего дерева.

Их не путать с **параметрами модели**, которые находятся в процессе `fit()` (коэффициенты, центроиды).

---

## 2. С помощью каких показателей можно оценить качество обучения модели с вещественными метками?

- **MSE** — среднеквадратичная ошибка.
- **RMSE** — корень из MSE (в тех же единицах, что и целевая переменная).
- **MAE** — средняя абсолютная ошибка.
- **R²** — коэффициент детерминации (доля объяснённой дисперсии).

---

## 3. С помощью каких показателей можно оценить качество обучения модели с целочисленными метками?

- **Accuracy** — доля правильных ответов.
- **Precision, Recall, F1** — для несбалансированных классов.
- **Confusion matrix** — таблица TP/FP/FN/TN.
- **ROC-AUC** — площадь под ROC-кривой.
- **Log-loss** — логарифмическая функция потерь.

---

## 4. Что показывает метрика Точность (Accuracy)? Пояснить на примере

Доля правильных ответов среди всех предсказаний:

**Accuracy = (число верных) / (общее число объектов)**

**Пример.** Классификатор на 100 объектов ириса ответил верно для 95.  
Accuracy = 95 / 100 = **0.95**.

Ограничение: при сильном дисбалансе классов метрика обманчива (если 95% — один класс, «глупый» классификатор тоже даст 0.95).

---

## 5. Какую информацию предоставляет метрика Матрица ошибок (Confusion Matrix)? Пояснить на примере

Таблица размера `K × K` (K — число классов), где по строкам — истинные классы, по столбцам — предсказанные. Диагональ — правильные ответы, вне диагонали — ошибки.

**Пример для двух классов:**

|  | Предсказан 0 | Предсказан 1 |
|---|---|---|
| **Истина 0** | TN = 50 | FP = 5 |
| **Истина 1** | FN = 10 | TP = 35 |

Показывает, **какие классы модель путает**, и служит основой для Precision, Recall, F1.

---

## 6. Что показывают метрики Полнота (Recall) и Точность (Precision)? Пояснить на примере

- **Precision (точность)** = TP / (TP + FP) — какая доля предсказанных «положительных» действительно положительна.
- **Recall (полнота)** = TP / (TP + FN) — какую долю реальных «положительных» модель нашла.

**Пример (медицина):** TP = 35 (больные, распознанные как больные), FP = 5 (здоровые, признанные больными), FN = 10 (больные, пропущенные).  
Precision = 35 / 40 = 0.875  
Recall = 35 / 45 = 0.778

**Смысл:** Precision важен, когда ложное срабатывание дорого (спам-фильтр). Recall — когда пропуск цели критичен (онкология).

---

## 7. Формула расчёта средней квадратической ошибки (MSE)

MSE = (1/n) · Σ (yᵢ − ŷᵢ)², где i = 1..n

Здесь `yᵢ` — истинное значение, `ŷᵢ` — предсказанное, `n` — число объектов.  
Чем меньше MSE, тем лучше.

---

## 8. Формула расчёта коэффициента детерминации (R²) и интерпретация

R² = 1 − SS_res / SS_tot

где:
- SS_res = Σ (yᵢ − ŷᵢ)²  — сумма квадратов остатков,
- SS_tot = Σ (yᵢ − ȳ)²   — общая сумма квадратов,
- ȳ — среднее истинных значений.

Интерпретация:
- R² = 1 — идеальное совпадение.
- R² = 0 — модель не лучше константного предсказания ȳ.
- R² < 0 — модель хуже константы (возможно при переобучении или на малой выборке).

---

## 9. Недостаток проверки модели на отложенных данных

- **Оценка зависит от конкретного разбиения** — при другом `random_state` результат может отличаться на 5–10%.
- **Часть данных «тратится»** на проверку и не используется при обучении — модель обучается на меньшем объёме, что особенно критично на малых датасетах.
- **Невозможно оценить разброс** качества модели, есть только одна цифра.

---

## 10. Достоинство перекрёстной проверки по сравнению с проверкой на отложенных данных

- **Каждый объект побывает и в обучении, и в тесте** — данные используются полностью.
- Результат — **среднее по k фолдам**, устойчивее к случайности разбиения.
- Можно посмотреть **разброс** оценок (std, min, max), а не одну цифру.

---

## 11. Как использовать кривые проверки для выбора оптимальной модели?

Кривая проверки показывает **качество как функцию гиперпараметра** (например, степени полинома). Строим две кривые:

- **train** — качество на обучении,
- **CV** — качество по кросс-валидации.

Выбираем гиперпараметр **в точке максимума CV-кривой** — там, где ещё нет переобучения (train сильно выше CV), но уже нет недообучения (обе низкие).

---

## 12. Как использовать кривые обучения для выбора оптимальной модели?

Кривая обучения показывает **качество как функцию объёма обучающей выборки** при фиксированной сложности:

- если обе кривые вышли на плато и близки — данных и сложности достаточно;
- если CV всё ещё растёт — **данных мало** (собираем больше);
- если большой зазор train ≫ CV — **модель переобучена** (снижаем сложность или добавляем регуляризацию).

---

## 13. Как использовать кривые проверки для выбора оптимальной модели?

См. ответ на **п.11**: строим `train` и `CV` как функцию гиперпараметра, выбираем значение в точке максимума CV — компромисс между недо- и переобучением.

---

## 14. Параметры утилиты `train_test_split(X, y, random_state=0, train_size=0.5)`

- **X, y** — массивы для разбиения: матрица признаков и вектор меток.
- **random_state=0** — seed генератора случайных чисел; фиксирует разбиение, чтобы результат был воспроизводим.
- **train_size=0.5** — доля объектов, попадающих в обучающую выборку (50%). Остальные 50% идут в тест. Альтернатива — `test_size`.

---

## 15. Какая метрика используется при построении кривых проверки?

По умолчанию используется **метод `score()`** переданной модели:

- для классификаторов — **accuracy** (или другая метрика, если задано `scoring=`),
- для регрессоров — **R²**.

Параметр `scoring` в `validation_curve`, `learning_curve`, `GridSearchCV` позволяет указать другую метрику (`"f1"`, `"roc_auc"`, `"neg_mean_squared_error"` и т. д.).

---

## 16. Параметры утилиты `GridSearchCV(PolynomialRegression(), param_grid, cv=7)`

- **`PolynomialRegression()`** — оценщик (модель), у которой перебираем гиперпараметры. Может быть как класс модели, так и `Pipeline`.
- **`param_grid`** — словарь вида `{"параметр": [значения]}` или список таких словарей. Например:
  ```python
  param_grid = {"degree": [1, 2, 3, 4, 5]}
  ```
  Если модель — `Pipeline`, ключи пишутся с префиксом: `"polynomialfeatures__degree"`.
- **`cv=7`** — схема кросс-валидации: число фолдов (`7`) или объект `KFold`, `LeaveOneOut` и т. п.

Результат: `grid.best_params_` — лучшая комбинация гиперпараметров, `grid.best_score_` — качество на кросс-валидации, `grid.best_estimator_` — обученная модель с лучшими параметрами.

## Кратко

| Метрика | Тип задачи | Формула / смысл |
|---|---|---|
| Accuracy | классификация | доля верных ответов |
| Precision | классификация | TP / (TP + FP) |
| Recall | классификация | TP / (TP + FN) |
| F1 | классификация | 2·P·R / (P + R) |
| MSE | регрессия | среднее (y − ŷ)² |
| R² | регрессия | 1 − SS_res / SS_tot |
